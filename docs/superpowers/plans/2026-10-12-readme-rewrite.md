# 根目录 README 重构计划

日期:2026-10-12 · 分支:`feat/self-hosted-backend`

## 目标

重写仓库根目录的 `README.md`,让它成为**给用户看的**产品首页:一个第一次打开仓库的人能在一分钟内弄懂「这是什么、能做什么、长什么样」,五分钟内能把它部署起来。

要求(来自用户):
1. 重构 `README.md`,读者是用户(想用、想自建部署的人),不是开发者。
2. **由我自己运行项目并截图**,截图要真实来自运行中的应用。
3. **文案交给 Opus 5.5 设计**(用 `Agent` 的 `model: "opus"`),我负责提供事实、审核准确性。
4. 先写计划(本文)。

## 现状与问题

当前 README(88 行)是上游 Enjoy 的宣传页和本分支说明的拼接:

- 开头的徽章、「网页版 enjoy.bot」「浏览器插件」「桌面版即将发布」、四张上游截图,都是**上游项目**的信息,和本仓库自建的 `server/` + `web/` 没有关系,会让用户以为这里能装插件或下桌面版。
- 本分支真正的内容(自建后端、手机网页版)只有两小段,且停留在 10 月初:缺少已经做完的功能——按住说话与实时通话、段位赛、联机练习、背单词、智能体、学习联动、管理后台。
- 开关(`RANK_ENABLED` 等)以代码块散落在部署说明里,用户分不清「默认有什么」「要自己打开什么」。
- 没有任何本应用自己的截图。

## 读者与定位

| | |
|---|---|
| 主读者 | 想给自己或小圈子搭一个英语口语练习站的人(有一台能跑 Docker 的服务器,自备 LLM/语音上游的 key) |

语气:中文、直接、具体;不夸大,不使用「颠覆」「革命性」之类词;不写任何没有依据的数字。

## 事实边界(写进文案的东西必须能核实)

沿用 `docs/CLAUDE.md` 的规则:**区分「已验证」和「未验证」,不编数字。**

- **功能清单**只写代码里已存在且默认可见或有开关说明的功能,来源是 `web/src/app.tsx` 的路由、`server/.env.example` 的开关、`docs/superpowers/specs/` 的一页摘要。由我整理成「事实清单」交给 Opus,Opus 不自行补充功能。
- **开关与默认值**从 `server/.env.example` 直接抄(`RANK_ENABLED`、`ROOMS_ENABLED`、`REALTIME_ENABLED`、`WORDBOOK_ENABLED`、`AGENTS_ENABLED`、`LINKS_ENABLED` 等),并在最终审核时逐个对照。
- **不写**延迟、成本、准确率等数字;如需提及成本,只指向 `server/README.md` 的「成本保护」。
- **截图里的 AI 回复来自本地假上游**(见下),README 里用语不得暗示这是真实模型的水平,也不在截图旁标注任何模型名。
- **未在真机验证的**(iOS Safari 录音、实时通话等)沿用 `web/README.md` 里已有的说法,不在首页夸口。
- 上游 Enjoy、《一千小时》、《人人都能用英语》要**保留署名与链接**,放在页面末尾的「致谢与相关阅读」。

8. **致谢与相关阅读**:上游 Enjoy、一千小时、《人人都能用英语》章节目录(保留现有链接),常见问题链接。

## 截图方案(我自己运行,不用真实上游)

### 运行方式
- **不用 Docker**(`CLAUDE.md`:容器只在用户要求时重建):本地 `uv run` 起 server,`yarn web:dev`/构建后的 `web/dist` 由 server 同源托管。
- 数据库用全新 SQLite,放在 scratchpad 目录;`REGISTRATION_MODE=open` 只用于这个临时实例;`ADMIN_USERNAME/ADMIN_PASSWORD` 用我临时生成的测试值,不写进任何入库文件、不在回复里复述。
- 打开 `RANK_ENABLED`、`ROOMS_ENABLED`、`WORDBOOK_ENABLED`、`AGENTS_ENABLED`、`REALTIME_ENABLED`(视是否能展示)等开关,让截图覆盖全部功能。
- **假上游**:在 scratchpad 里写一个本地 OpenAI 兼容的小服务(`/chat/completions` 流式、`/audio/speech`、`/audio/transcriptions`),让对话、朗读、识别页面有内容;讯飞评测用假的 `FakeXfyun` 同类思路或直接向库里写入评测记录与 WAV(用 `server/tests` 里已有的 `make_wav` 思路)。**不调用任何真实上游,零成本、不泄露密钥。**
- 假上游、种子脚本、临时库全部放 scratchpad,**不提交**;最终只提交 PNG/JPEG 和 README。

### 种子数据(全部虚构)
用户名 `demo`、`alice` 等明显的演示账号;对话主题用咖啡店点单、旅行问路这类中性内容;评测分数取不同档次以展示颜色;词汇本、词书进度、段位与成就用 API 或脚本造数。不出现真实姓名、邮箱、密钥、域名、IP。

### 截图清单与规格
- 视口 **390×844**(手机),浅色为主;题图拼图可用 2–3 张深色穿插,前提是视觉统一。管理后台用手机宽度 + 一张桌面宽度。
- 清单(按页面):登录 · 练习首页 · 跟读评测结果 · 对话(文字 + 语法批注)· 按住说话/语音消息 · 实时通话 · 查词 · 词汇本 · 背单词首页/词卡/复习 · 段位 · 联机房间 · 智能体设置 · 进度 · 管理后台概览/用户内容/录音回放。**页面是否存在以截图当天的路由为准**,缺失的功能不凑数。
- 隐私与安全检查:截图前确认地址栏、开发者工具、通知、系统托盘不入镜;页面里无 token、无 `.env` 内容;截完逐张查看。
- 文件:`docs/images/readme/<序号>-<名称>.png`,单张 ≤ 250 KB(PNG 量化或转 JPEG 质量 85),统一尺寸;README 里用相对路径引用并写 `alt`。`docs/CLAUDE.md` 的目录说明补一行 `images/readme/`。
- 截图用内置浏览器工具(`resize_window` 手机预设 + 逐页 `screenshot`),必要时用 Playwright 保存无损文件;若内置浏览器的截图无法落盘成文件,则改用 `web/` 已安装的 Playwright 截图到文件。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 假上游的 AI 回复被读者当成真实效果 | 文案不写模型名与质量;回复内容保持中性、简短 |
| 截图含敏感信息 | 全虚构种子数据;逐张查看;不含地址栏与系统界面 |
| 某些功能(实时通话、联机)在无真实上游时无法展示 | 能用假上游或种子数据做出静态画面的才拍,拍不出来的不放,不拼接伪造 |
| 文案夸大或与代码不一致 | 事实清单约束 + 我逐条审核开关名与默认值 |
| 图片拖慢仓库与页面 | 单张 ≤ 250 KB,总量控制在约 3 MB 内;不入库原始大图 |
| README 过长 | 首屏(题图 + 简介 + 功能总览)必须一屏内能读完;细节外链到 `server/README.md` |
