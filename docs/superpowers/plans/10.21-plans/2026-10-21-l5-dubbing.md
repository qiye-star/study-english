  新表 `library_dubs`、`library_attempts.dub_id`(String(36),可空,无外键,与 `assessment_id` 同语义)+ 索引 `ix_library_attempts_dub_id`。

  `down_revision` = 合并时的头(Task 0a 核对:L3 的 0028 已合并则接 0028,否则接 0027;撞号按 INDEX §3「后合并者改号」)。
  `library_dubs` 列:`id` String(36) PK、`user_id` FK users CASCADE、`item_id` FK library_items CASCADE、`seg_from` / `seg_to` Integer、`role` String(2)、

- **R3 角色的取值。** `speaker` ∈ `A`…`F`(`MAX_ROLES = 6`,占位)或 `NULL`(未标注);角色名 `role_names` = `{"A": "名字", …}`,
  名字压空白后 1–24 字符、只存在已用到的键;名字与句子一样是用户内容,不进日志 / 审计 / 计量 / URL。未标注的句子在配音里一律当「对方」(照常出声)。

- **R4 精选库的角色:管理员标一次,下发到副本。** 已核对:`catalog_store.add_to_library`(`server/app/library/catalog_store.py:289`)在加入时把目录句子逐行
  复制成 `LibrarySegment`(`:307`),之后副本**不随目录改字**(`admin/src/features/catalog/CLAUDE.md`「已加入的学习者副本不随目录更新」)。
  裁定:
  1. `add_to_library` 复制时带上 `speaker` 与 `role_names`(一行改动)。
  2. 管理员保存角色时,`library/roles.sync_catalog_roles` 把角色同步到**所有已有副本**:副本的 `role_names` 整体替换;句子只在「同一 `idx` 且
     `store.same_text` 相同」时改 `speaker`(用户改过字的句子不动)。理由:角色是标注元数据而不是文字;管理员通常在发布之后才补标注,
     不同步的话早加入的人永远没有角色。这与 `sync_copies`(`catalog_store.py:389`,媒体替换后副本跟随)同一思路,单独一个函数,不改 `sync_copies`。
  3. 副本对用户**角色只读**:`PUT /api/dubbing/items/{id}/roles` 与「智能建议」对 `catalog_id` 非空的条目返回 409 `Roles are set by the editors`;
     网页在副本上隐藏标注控件。目录还没标注时,网页说明「精选素材的角色还没有标注」,仍可选「全部句子都是我」以外的片段吗——不可以:没有角色就不能配音
     (见 R6 第 4 条)。
  4. 已发布的目录条目**可以**改角色(角色不改文字,与「已发布不能改句子」`catalog_admin.py:364` 的规则不冲突)。

- **R5 重新分句 / 改字时保留角色。** `store.write_segments`(`store.py:121`)整表替换句子:新句的 `speaker` 取旧句中文字(压空白后)相同者,

  结果页标「句子已变化」,不删。

- **R6 片段规则(服务端强制;数值是占位,未验证)。**
  1. 连续:`seg_from ≤ seg_to`,都在 `[0, seg_count)`;片段 = 两端之间全部句子。
  2. `seg_to − seg_from + 1 ≤ MAX_LINES = 12`;`segs[seg_to].end_ms − segs[seg_from].start_ms ≤ MAX_MS = 90_000`。
  3. 常量只在 `server/app/dubbing/clip.py`,经 `GET /api/dubbing/config` 下发给网页(网页只做提示,以服务端为准)。代码注释与 README 写明「占位,未用真实素材校准」。
  4. 选定的 `role` 在片段里至少有 1 句;片段里所有句子都是同一角色也允许(独白)。片段里没有任何角色标注 → 400 `Role has no lines in the clip`。

    回复格式 `N. X`(X ∈ A–F),解析沿用 `ai.parse_translations` 的行正则思路,只收 1..N 与合法字母。

- **R9 评分只经现有接口。** 已核对 `POST /api/speech/assessments`(`server/app/routers/speech.py:132`):`save=true` 时校验来源(`SOURCES` `:35` 已含 `library`)、

- **R11 打分(权重与曲线全部是占位,待真机样本校准)。** 纯函数在 `server/app/dubbing/scoring.py`,单独的测试文件穷举分支。
  - 单句:`score = round(0.6·发音 + 0.2·流利 + 0.2·同步)`;发音 = ISE `pronunciation_score`,流利 = `fluency_score`(都已在 `Assessment.result` 顶层)。
  - **同步度**(0–100),参照原句 `[start_ms, end_ms]`:
    - 用词偏移得到「开口」区间:取 `detail_result.words` 中 `error_type != "Omission"` 且 `duration > 0` 的词,`spoken_start = rec_start_ms + 首词 offset`、
      `spoken_end = rec_start_ms + 末词 (offset + duration)`;偏移单位是 100 ns(÷ 10 000 = ms,见 R12)。
    - `onset = 100` 当 `|spoken_start − start_ms| ≤ 400`(**±400 ms 容忍**,吸收麦克风 / 播放延迟);超出后线性降到 0(再过 `ONSET_FALLOFF_MS = 1000`)。
    - `ratio = (spoken_end − spoken_start) / (end_ms − start_ms)`;`duration = 100` 当 `0.8 ≤ ratio ≤ 1.25`,向 `0.4` / `2.5` 线性降到 0。
    - `sync = round(0.5·onset + 0.5·duration)`,`sync_basis = "words"`。
  - **偏移不可用时只看时长比**(用户要求的回落):判定「不可用」= 没有满足条件的词 / 偏移不是非递减 / 末词结束晚于 WAV 时长 + 100 ms / 全部偏移为 0。
    此时 `ratio` 改用网页上报的 `voiced_ms`(能量门限测得的有声时长,见 R13),`sync = duration`,`sync_basis = "duration"`。
    网页走 MediaRecorder 回落采集(R13)时开口时刻不可信:即使词偏移可用也只算时长比(`sync_basis = "duration"`)。
    两者都没有 → `sync = None`、`sync_basis = "none"`,该句按 `发音 75% + 流利 25%` 重新归一。
  - 整段:`total = round(平均(角色句的 score))`,没录到 / 无语音 / 评测失败的句子按 0 计并在 `lines` 里标 `missing`;
    `summary` = 已录句的发音 / 流利 / 同步平均(各自取整,`None` 跳过)。
  - `lines` JSON:`{"<idx>": {"assessment_id", "pronunciation", "fluency", "sync", "sync_basis", "score", "onset_ms", "ratio_pct"}}`;
    并发写同一行用进程内每 take 一把 `asyncio.Lock`(`WeakValueDictionary`,与 `library/ai.py:181` 的 `_CATALOG_LOCKS` 同一做法;单 worker 前提见
    `server/app/library/CLAUDE.md`)。

- **R12 逐词偏移:已核对什么、没核对什么。**
  - 已核对(代码):`providers/xfyun_result.py:6` `TICKS_PER_FRAME = 100_000`(注释「ISE positions are 10 ms frames; Azure uses 100 ns ticks」),
    `_timing`(`:58`)把 `beg_pos` / `end_pos` 换成 `offset` / `duration`(100 ns 刻度);`to_assessment`(`:132`)只保留非 `sil` 且有分数的词(`_is_speech_word` `:128`),
    每词带 `offset`、`duration`、`pronunciation_assessment.error_type`(`Omission` 由 `dp_message == 16`,`:9`)。`tests/test_xfyun_result.py:59` 断言
    `hello` 的 `offset == 1 * 100000`;夹具 `tests/fixtures/ise_good.xml` 的首词 `beg_pos="1"`,其间有 `sil` 词(`:17`)。
    `save_assessment` 把整个 `result` 存进 `assessments.result`(`assessment_store.py:35`),所以服务端可以事后读偏移。
  - **未验证:**(a)真实上游的 `beg_pos` 是否从上传 PCM 的第一个采样起算(还是从讯飞自己的端点检测起点);(b)漏读词(Omission)的 `beg_pos` / `end_pos` 取值;
    (c)精度是否够做 ±400 ms 判断。`ise_good.xml` 是否为真实上游录下的样本也未确认。Task 0a 只做代码层核对;真实样本核对放进设备清单
    (第 8 条),需要用户同意花评测费用。

- **R13 采集:一次开麦、按窗口切片(不用 `useRecorder` 的逐次开麦)。** 已核对两点使 `useRecorder` 不适合直接用于配音:
  (1)`useRecorder.start()` 每次都调启动器重新 `getUserMedia`(`web/src/audio/use-recorder.ts:91`),配音的每句窗口在播放中由时间轴触发,不在用户手势里,
  iOS 上能否在手势外重新开麦**未验证**,且每次开关麦都有启动延迟;(2)PCM 路径的结果会被 `trimSilence` 裁掉首尾静音(`web/src/audio/pcm-recording.ts:47`),
  WAV 的第 0 个采样不再对应窗口起点,词偏移就无法换算成视频时间。裁定:
  - **主路径(PCM):** 点「开始录制」的同步阶段 `decideCapture()`(`web/src/audio/capture.ts:337`)→ `startPcmCapture({ context, collect: false })`(`:90`)
    整段只开一次麦;`onFrame`(16 kHz 帧)累加采样计数;窗口打开时记 `(startSample, rec_start_ms = 当时的媒体毫秒)`,关闭时取到 `endSample`,

## 风险与未验证项

- **未验证(真实上游):** 讯飞 ISE 的 `beg_pos` 起点与精度(R12);Omission 词的偏移;一次 12 句并发评测时上游的并发限制与超时。
- **未验证(真机):** iOS Safari 在视频播放中开麦后的音频会话切换(播放音量下降、改走听筒、`muted` 切换延迟);Android Chrome 同时播放与采集时 worklet 是否持续出帧;
  外放时回声消除能否把原声挡在窗口外;蓝牙耳机的输出延迟对同步度的系统性偏移;`decideCapture` 在两平台实际走 PCM 还是回落。
- **占位数值(未校准):** 12 句 / 90 秒、窗口 −300 / +600 ms、±400 ms 容忍、`ONSET_FALLOFF_MS`、时长比区间、60/20/20 权重、并发 2、等待 60 s、建议额度 120 句 / 40 句一段。
- 字幕逐词高亮是线性估计,不是真实词时间;语速变化大的句子会提前或滞后。
- 配音成绩计入跟读最好成绩(R10),可能让「最好成绩」偏向配音(配音窗口更宽松);若用户不希望,第二期改为只在 `dub_id IS NULL` 时计入。
- `rec_start_ms` 与 `voiced_ms` 由客户端上报,用户能刷高自己的同步分;只影响本人的成绩,接受。
- 精选副本角色只读:管理员没标的精选素材不能配音(R4),依赖管理员的人工量。
- 共享文件的锚点改动(`models.py`、`main.py`、`test_architecture.py`、头断言、`architecture.test.ts`、`links-matrix.test.tsx`)与 L1 / L3 / L4 可能冲突,合并时按 INDEX §6 手工解决并记进 results。

## 设备清单(真机;每条记录机型 / 系统 / 浏览器 / 耳机类型 / 结果 / 日期;没跑的保持「未验证」)

7. 蓝牙耳机:同一个人用有线与蓝牙各录同一片段,对比同步分是否有系统性差异(用于决定是否做延迟校准)。
