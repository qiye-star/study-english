## 本计划的裁定

- **R1 端口放在 `services`,不放 `wordbook`。** 题目建议的 `wordbook/scheduling.py` 不可行:唯一写入点 `apply_review` 在 `services/vocabulary.py`,
  被生词本路由和背单词共用,而 `services` 层不能导入 `wordbook`(`tests/test_architecture.py:31`)。所以端口是 `services/scheduling.py`(纯,不 import `fsrs`),
  适配器是 `services/srs_fsrs.py`(全仓唯一 import `fsrs` 的文件,由新架构测试守着)。`vocabulary.py`、`wordbook/*` 都不直接 import `fsrs`。
- **R2 双写:FSRS 状态总在更新,开关只决定谁定排期。** 每次经过端口的写入(`apply_review`、`apply_lapse`)都同时算 Leitner 结果和 FSRS 结果:
  - Leitner 模式(默认):`box / due_at` 取 Leitner(与今天逐位相同),FSRS 四列取 FSRS 的结果(影子状态);
  - FSRS 模式:`due_at` 取 FSRS,`box = derive_box(stability)`,FSRS 四列同上。
  好处:两套状态始终都是新的,切换不需要一次性重算,也不会因为切换造成积压;切回 Leitner 时它从推导出来的盒子接着走。代价:关闭时也执行 FSRS 计算(纯 Python、无 I/O)。
- **R3 盒子推导 = 播种的反函数。** `seed_stability(box) = INTERVAL_DAYS[clamp(box)]`;`derive_box(S) = max{b : INTERVAL_DAYS[b] ≤ S}`,S < 1 → 0。
  因此 `derive_box(seed_stability(b)) == b`(往返不变)。熟练(`MASTERED_BOX = 4`)⇔ S ≥ 15 天。
  Spec §2.3 的「≥ 21 天 ≈ 掌握」只是例子;选 15 是为了往返不变、旧用户切换当天熟练数不跳。阈值放在 `scheduling.BOX_FLOORS`(= `INTERVAL_DAYS`),回放后可调(调了要同时改迁移回填的说明)。
- **R4 FSRS 配置:无短期步长、无模糊。** `Scheduler(learning_steps=(), relearning_steps=(), enable_fuzzing=False, maximum_interval=MAX_INTERVAL_DAYS, desired_retention=retention)`。
  理由:(1)本产品复习按「本地日」计划与计数,10 分钟步长会让同一词当天反复到期,每次 `reps + 1` 还会产生段位 `vocab_review`(刷分路径);
  (2)模糊用全局随机数,不可复现,破坏黄金测试与回放的确定性。`MAX_INTERVAL_DAYS = 365` 是**占位**(Leitner 封顶 30 天,一步放到 36500 太激进),回放后定。
- **R5 评分映射。** 端口的输入等级 `forgot → Again`、`hard → Hard`、`good → Good`、`easy → Easy`。Leitner 把 `easy` 当 `good`(所以 flag 关时行为不变)。
  `easy` 只在这里产生:`grading.review_grade(outcome, hinted, *, qtype, elapsed_ms, length)` —— `qtype ∈ {"spell","dictation"}`、`outcome == "correct"`、未提示、
  `elapsed_ms is not None` 且 `elapsed_ms ≤ EASY_BASE_MS + EASY_PER_CHAR_MS × length`;否则等于 `srs_grade(...)`。
  `EASY_BASE_MS = 3000`、`EASY_PER_CHAR_MS = 350` 是**占位**,没有任何数据支撑。按句拼写(`spell_ctx`)、选择题、快速回忆、生词本都不出 Easy。
  **响应里的 `grade` 字段仍是 `srs_grade` 的三值**(契约 `tests/fixtures/wordbook_contract.json` 不变,网页不需要认识 `easy`)。
- **R6 FSRS 列为空 = 「按盒子现播种」。** 任一行 `fsrs_state IS NULL` 时,端口先用 `(box, last_review = last_reviewed_at or created_at)` 播种为
  `State.Review, S = seed_stability(box), D = LEGACY_DIFFICULTY`,再评分。于是:新建行(`store.create_item`、生词本加词、`links/word_actions.py`)**不用改**;
  当天新词的盒子调整(`recall.py` 规则、`store.set_learn_box`)继续只看盒子;`set_learn_box` 额外把四列置空(下次复习按新盒子重播种)。`pull_due` 只改 `due_at`,不碰 FSRS 列。
- **R7 迁移 0028 与回填,可逆范围写清楚。** 加列全部可空:`vocabulary_items.stability FLOAT`、`difficulty FLOAT`、`fsrs_state SMALLINT`、`last_review TIMESTAMPTZ`;
  `wordbook_events.reviewed_at TIMESTAMPTZ`。回填:
  - `reps > 0` 的行:`stability = CASE box ...`(盒 ≤ 0 → 1,0..5 → `INTERVAL_DAYS`,> 5 → 30)、`difficulty = LEGACY_DIFFICULTY`(Task 0 算出后写成字面量)、`fsrs_state = 2`、`last_review = COALESCE(last_reviewed_at, created_at)`;
  - `reps = 0` 的行保持 NULL(R6 现播种,与当天学新词规则一致);
  - `wordbook_events` 中 `kind = 'review'` 的行:`reviewed_at = created_at`。
  **可逆性**:upgrade 只新增列、只写新列,不改 `box / due_at / reps / lapses / last_reviewed_at` 任何一行;downgrade 删掉 5 列 → Leitner 状态完整保留,
  丢失的只有升级后累积的 FSRS 状态与 `reviewed_at`(可从 Leitner 状态重新播种,但历史 FSRS 演化不可恢复)。迁移**不 import `fsrs`**(常量写死),以后升级库不影响迁移。
- **R8 「精确时间戳」= `wordbook_events.reviewed_at`。** 如实说明:现有 `created_at` 已是带时区、微秒精度的写入时刻;INDEX §3 冻结了「加精确时间戳」,本计划把它定义为
  **调度时刻**:只在这次事件真的经过端口改了排期(`apply_review` / `apply_lapse` 成功)时等于传给调度器的 `now`,否则 NULL。
  这样以后的优化器能区分「改了卡片状态的复习记录」和自由练习 / 未到期答对(现在两者都是 `kind="practice"`,分不开)。
  评分(1–4)不另存列:INDEX 冻结了形状;回放用 `grading.event_grade(qtype, outcome, credit)` 从事件反推(提示会把 `credit` 减半,所以 hard / good 可分);**Easy 不可反推**,记入风险。要存 rating 先改 INDEX。
- **R9 目标保持率:全站设置,不做每用户。** `wordbook_fsrs_retention_pct: int = Field(90, ge=85, le=95)`(整数百分比,注册表 `min=85, max=95`),传给调度器时 ÷ 100。理由:
  (1)wordbook 没有每用户设置表,现有每用户偏好只有 `defpref` 事件这一种绕法(`store.py:287`),再加一种要另开存储、限流和三语界面,超出本车道;
  (2)保持率直接改变复习量,和每日复习上限(goals v2)互相影响,普通用户难以判断,灰度期间也需要全站一致才能比较;
  (3)回放工具按保持率扫描(0.85 / 0.90 / 0.95)给出依据,管理员调一处即可。每用户覆盖留作后续(见「不做」)。
- **R10 灰度开关与一致性。** `wordbook_fsrs_pct: int = Field(0, ge=0, le=100)`,默认 0 = 全员 Leitner。用户分桶
  `bucket(user_id) = int.from_bytes(sha256(f"fsrs-rollout:{user_id}").digest()[:4], "big") % 100`,`bucket < pct` 用 FSRS。
  - 同一用户在 pct 不变时永远同一引擎(确定、无状态、多进程一致);pct 只升不降时,已切换的用户不会被切回(单调)。
  - **降低 pct 就是回滚**(设置项 `danger` 文案写明);因为 R2 双写,来回切不会制造积压:切换只影响「下一次复习」怎么排,不重写已有 `due_at`。
  - 两个写入方(背单词 `_write_srs`、生词本 `POST /vocabulary/{id}/review`)都用 `policy_for(settings, user_id)`,同一用户同一时刻不会出现两种引擎。
- **R11 乐观条件不变。** `apply_review` 仍只以 `reps == seen_reps` 为条件、仍用调用方传入的 `seen_box` 算 Leitner;FSRS 快照在同一会话里按
  `(id, user_id, reps == seen_reps)` 先读一次,读不到直接返回 `False`(与 0 行更新同义)。`apply_lapse` 仍以 `reps` + `box` 为条件、盒 ≤ 0 不写。

## 灰度操作手册(写进 results 文档;每一步都由用户决定,不自动执行)

1. 合并、部署(`wordbook_fsrs_pct = 0`)。此时只有双写,用户无感。
2. 在**备份副本**上跑 `python -m app.admin.fsrs_replay --retention 85,90,95 --out <scratch>/replay.json`(只读;不要对生产库直接跑大查询)。
3. 判据(建议,用户拍板):FSRS(0.90)的 log loss 与校准误差不劣于 Leitner 隐含预测;平均间隔与日均复习量变化在可接受范围。数字只来自回放输出,不预设。
4. `wordbook_fsrs_pct`:10 → 观察 ≥ 7 天 → 50 → 100。观察口径:回放工具 `--since <切换日>` 对 `reviewed_at` 非空的事件按「当前 pct 下的分桶」统计实际答对率(本期不另做在线面板)。
5. 回滚:把 pct 调回 0(或更低)。不需要迁移、不需要回填;Leitner 从推导盒子继续。极端情况才 `alembic downgrade 0027`(丢 FSRS 状态,见 R7)。

## 风险与未验证项

- **未验证**:`fsrs` 任何行为都没在本机跑过;API 表是读 main 分支源码得来,锁定版本的行为由 Task 0 核实。
- **未验证 / 占位**:`LEGACY_DIFFICULTY`、`MAX_INTERVAL_DAYS = 365`、`EASY_BASE_MS / EASY_PER_CHAR_MS`、熟练阈值 S ≥ 15。都需要回放或真实数据定稿。
- **回放偏差**:历史复习都发生在 Leitner 的到期时刻(选择偏差);起始盒子和 lapse 是近似(R8、Task 9);Easy 不可从历史反推;Leitner 的「隐含预测」是我们定义的,不是 Leitner 自带的。回放结论只能作参考,不是证明。
- **复习量变化**:FSRS 间隔可能远长于 30 天,`due_keys` 的到期数会下降,「每日复习上限 / 达标」体验会变;也可能对困难词更频繁。灰度观察。
- **双写成本**:关闭时每次复习多一次 SELECT 和一次纯 Python 计算;应很小,**未测**。
- **回滚语义**:切回 Leitner 后,盒子是 FSRS 推导值,不是「如果一直用 Leitner」会有的盒子;两套状态都保留,但 Leitner 不会「穿越」回原轨迹。
- **文件冲突**:`wordbook/service.py` 不在 INDEX 所有权表里,L4 可能同时改(例句选择);合并时手工解决。`routers/vocabulary.py`、`store.py` 同理。
- **多进程**:分桶是纯哈希、设置热更新;若多个 worker 读到设置的时间不同,同一用户在几秒内可能遇到两种引擎 —— 因 R2 双写与 R11 乐观条件,结果仍一致(只是那一次排期由不同引擎决定)。
- **Postgres**:迁移回填与 `FLOAT/SMALLINT` 只在 SQLite 测试里跑过的写法上设计;Postgres 上**未验证**。
- 真机:本车道只有网页一处请求体改动,无设备清单。
