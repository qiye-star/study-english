## 3. 对账结果

- 两份计划互相对账过(服务端计划末尾的「与网页计划的对账」14 条):服务端已**收窄线上字段**去匹配网页的契约测试,网页**不需要改动**。
- 取消了服务端原先加的两项:`GET /api/rooms/{id}/agents` 里的 `default_agent`,以及 `agent_tutor` 帧里的英文 `hint`。线上新增的只有:`say.to`、语音表单 `to_agent`、`meta.note_zh`、`done.note_zh`、`agent_trace.note_zh`、`tutor.hint_zh`、通知码 `voice_unclear`、设置 `zh_note`。全部是可选键,缺省 = 没有。
- 一个可选的网页小调整:带练进行期间,非被点名的成员打开「对象」发的消息服务端会忽略 `to`(不路由),网页那句「消息会交给 X」对他们略有出入。

## 4. 对设计文档的裁定(服务端计划里已写成 Ruling,spec 不改)

- **静音与关闭的优先级**:智能体总开关关闭的 `agent_off` 先于房间静音的 `ai_off`。
- **带练期间不路由隐式消息**:带练进行中,只有被点名成员的回答被当作回答;「对象」和回复规则触发的普通回合暂不路由(避免与带练抢答)。
- **语音 `to_agent` 的校验分两步**:上传时只校验形状(REST 拿不到房间配置),转写成功后再按房间配置校验。
- **`@ai` 的房间等级与场景上下文**:旧的 `@ai` 带房间等级 / 场景提示;改为智能体后改用角色自己的水平设置,不再保留旧上下文。
- **`@` 点名不存在的智能体**:当作普通消息,落到后面的隐式规则。

## 5. 风险

1. **不保留旧行为**(D3):智能体总开关关闭时,房间里没有任何 AI 回答(`@ai` 只给 `agent_off`)。这是用户的决定,服务器上必须 `AGENTS_ENABLED=true`。
2. **「对象」打开期间每条消息都是一次模型调用**:受每房间 / 每人 / 全站上限约束,界面常驻提示;带练外不自动打开。
3. **纯英文 + 兜底过滤**:服务端把含中文的句子从公开文本移走,极端情况下可能误伤含中文人名的句子(人名保留,朗读时跳过)。
4. **主包体积**:网页计划要求新增文案走懒加载,体积报告随计划交付。
5. 计划里的测试和实现代码**尚未实跑**;真实上游、真机(输入法、iOS 音频)、Postgres 都未验证。
