视觉规格(玻璃版)

项数值 / 规则
玻璃参数与跟读库稿相同:blur(34px) saturate(2);弹窗用「强面」:深色填充 rgba(120,140,230,.17)、高光边 rgba(255,255,255,.26);浅色填充 rgba(255,255,255,.62)(比库稿 .55 略实,保证浅色下压暗背景上的正文对比度)、高光边 .85。顶部再叠一层 120px 的淡高光渐变(纯背景,不是模糊)。
形状弹窗距屏幕左右下各 10px,圆角 34(=手机圆角 44 − 10,同心);内部卡片圆角 20–22,按钮 / 芯片为胶囊形。
每屏模糊层数2 层(上限 3):① 对话顶栏(玻璃胶囊)② 跟读弹窗。遮罩只压暗、不加模糊(否则对话会被模糊两次,且多一层);弹窗打开时底部输入栏在弹窗正下方,去掉它的模糊(只留半透明填充),避免两层模糊叠在同一块区域。弹窗内的参考句卡、录音面板、成绩卡、逐词卡、列表行、芯片全部是 .tint(半透明 + 高光边),不加 backdrop-filter(嵌套模糊也只能采样到父层,看不出效果)。
文字对比正文用 --ink,次要文字深色 #b3b9c8 / 浅色 #4f586a(都比库稿略加深 / 提亮一档,因为弹窗背后是压暗后仍带颜色的气泡);遮罩深色 .52 / 浅色 .30。
动效只动 transform / opacity / background-position:弹窗入场(上浮 60px + 缩放 .97,0.62s 弹性曲线)、内容依次浮入(每项 45ms)、波形竖条 scaleY、红点扩散、进度条 scaleX、流光字 background-position、圆环用两个半圆旋转实现(不重绘 conic 渐变)、横条 scaleX、逐词淡入上浮、火花。持续动画只在:主按钮光带、录音中、评测中、极光背景。
降级低端机 .lite(沿用 glass-quality.ts):玻璃退为实色 --solid,极光减半且静止,所有动画关闭,圆环与数字直接显示终值,跟随高光关闭。prefers-reduced-motion:同样全部静止(模糊保留)。iOS 需带 -webkit-backdrop-filter。
深浅色正式版跟随 html.dark(外观设置或系统);页面上方的切换只是给本稿看效果用的。

设计要点(我的看法)

点做法与理由
全局只挂一个弹窗挂在应用外壳里(和「选词查词」同一位置),各处调用 openShadow(text, {list, index}) 打开;调用方先关自己的面板再打开。不叠加两层弹窗:项目里有记录,嵌套弹层会让两套焦点陷阱互相递归卡死。玻璃版同理:句子列表 → 跟读是同一块玻璃换内容,关闭确认也画在弹窗内部,不是第二个弹层。
复用而不是重写把练习页里的「录音 → 转 WAV → 评测 → 保存」抽成一个钩子,练习页和弹窗共用;评分环、逐词着色复用现有组件的数据与配色规则(逐词着色只用简化的行内着色,不带 wavesurfer 波形,波形留给完整页)。玻璃外观只是一层样式。
多句连续练从一条消息的句子列表进入时,弹窗带「第几句 / 共几句」、位置圆点和「下一句」;从单句入口(选词查词、语法纠正)进入时不显示。录音 / 评测中上一句、下一句变灰(本稿比 v1 多的一条小限制,避免录到一半换句)。
录音时锁关闭录音和评测中,下拉关闭 / 点遮罩 / 点 × 会先询问「放弃这次录音?」,防止误触丢掉(本稿把 v1 的浏览器 alert 画成了弹窗内的确认卡)。
成绩照常保存仍然 save: true,在「练习 → 历史」里能找到;弹窗里只多一个「查看完整详情」跳转,不强制。
懒加载弹窗、钩子和玻璃样式放进动态加载的块,对话页首屏体积不增加;不改 theme.css 全局令牌,只在弹窗根节点上定义作用域变量。
保留练习页练习页本身不动(自由输入文本练习、历史、列表),只是对话里的 6 处入口不再跳去那里。
玻璃只两层顶栏 + 弹窗;遮罩、输入栏、弹窗内所有卡片都不模糊。高度随状态变化时只做内容淡入,不动画高度(不触发布局)。

风险与我没法保证的

  • iOS 麦克风授权必须在点击手势内触发 getUserMedia;弹窗里的「录音」按钮是这个手势,但真机上的授权弹窗、音频路由(录音时停掉范读)未验证。
  • 与选词查词叠加:弹窗里的参考句可以长按选词(沿用现有选词操作条);操作条和弹窗底部按钮的叠放位置需要真机确认。录音中暂停选词操作条,避免误触。
  • 练习页的重构风险:抽钩子会动到现有练习页,要靠它现有的测试兜住;这是改动里最需要小心的一处。
  • 真机模糊性能与耗电未验证:34px 模糊盖住大半屏、上面还在跑波形动画,中低端安卓可能掉帧;靠 .lite 兜底,但阈值要真机定。
  • 对比度依赖背后内容:对话里如果正好是大块蓝色用户气泡,浅色主题下弹窗边缘会偏蓝;已用更实的填充(.62)+ 遮罩缓解,只在本稿(Chromium)里目测过,Safari 的模糊与饱和效果未验证。
  • 两个半圆拼成的圆环在 12 点和 6 点可能有 1px 接缝(抗锯齿),真机高分屏上要看一眼。

需要你拍板

16 处入口(对话提示、语法纠正、复盘、转写详情、句子列表、选词查词的「跟读」)全部改成弹窗,还是只改对话里的 5 处、选词查词保持跳转?我推荐全部改,行为一致。
2弹窗里的逐词着色:我推荐简化版(行内着色,点词查词),不带波形。要完整波形的话弹窗会很高、也更重。
3「下一句」连续练:我推荐只在多句列表入口出现。要不要连「自动播范读后立刻录音」这种全自动模式也做?我不推荐(iOS 音频冲突风险)。
4对话页背景要不要加极光色块?玻璃要"后面有颜色"才好看;不加的话弹窗背后只有气泡,效果接近磨砂白 / 磨砂黑。已定(用户):只在弹窗打开时、遮罩下方淡入极光(0.7 秒,纯 CSS 色块),弹窗关闭后淡出,对话页平时保持现状。演示里点「关闭 / 打开弹窗」可对比。
5悬浮(四周留边)还是贴底?本稿是悬浮玻璃板(更像卡片,背后透出更多对话);贴底版全宽、可用宽度多 20px。我推荐悬浮。
6样式放哪:规范 §11.4a 把玻璃样式限定在 features/library/ 内。跟读弹窗属于练习 / 对话,我推荐把 .glass 令牌抽成一个两边懒块都引用的小样式文件(仍不进主包、不改 theme.css),这需要在计划里写一条 Ruling。
