## 3. 免 @ 对话(联机)

### 3.1 现状(已核对代码,计划作者再核一遍)
- `connection.say` 里:`@ai` 先走旧通道;否则以 `@` 开头才尝试 `agents.admit` 匹配智能体名;带练时只有 `kind == "text"` 的消息才会被 `agent_tutor.on_message` 当作回答,**语音消息不计**。
- 语音消息经 REST 上传、发送后异步转写(`rooms/voice.py`),没有任何路径把转写结果交给智能体。

### 3.2 四件事
1. **回复即对话。** 发送一条消息时,若 `reply_to` 指向的消息是某个智能体发的(消息元数据里有智能体身份,核对 `agent_lane` 写入的字段),服务端自动把这条消息路由给**那个**智能体,不需要 `@`。文字和语音都适用;`@名字` 与 `@ai` 优先于回复规则。
2. **「对象」标签。** 输入栏显示「对 <默认智能体名> 说」的开关(房间里有两个智能体时可选其一)。打开后,本人发的文字和语音都路由给该智能体;关闭后只发给房间。**只对本人生效,按房间记在本机**(localStorage,取不到时当作关闭);**带练开始时自动打开,带练结束(完成、停止、关闭房间)时自动关闭**;没有空闲自动关闭(D2)。服务端不保存这个开关:客户端在每次发送时带上 `to`(§3.4),这样旧客户端和未打开的人完全不受影响。
3. **带练时语音也算回答。** 轮到你时发的语音,转写完成后的文字当作你的回答(与文字回答走同一个 `_advance`);带练期间轮到你时**不需要**开「对象」也不需要 `@`。转写失败 / 为空 → 不计入,界面提示「没听清,再说一次」,计时不重置也不扣题。
4. **`@` 补全。** 输入框里输入 `@` 弹出可选的智能体名字(含 `@ai` 的别名项「AI」),点一下补全;作为兜底,键盘 / 触屏都可用。

### 3.3 成本与约束
- 路由到智能体的每条消息都是一个智能体回合:沿用现有所有上限(每房间每小时、每人每天、全站每天、`ROOMS_AI_*` 与 `AGENTS_TURNS_*` 取更严)和「一房间同时只有一个 AI 发言者 + 队列上限」;超限给 `ai_quota` / `ai_busy` 提示,**不丢消息**(消息照常发布,只是不触发回答)。
- 「对象」打开期间,每条消息都计一次回合:界面在输入栏常驻显示小提示「消息会交给 Emma」,避免忘记关。
- 房间被静音 `ai_muted`、公共 AI 关闭 `ai_public=false`、智能体被停用时,「对象」标签置灰并说明原因。

### 3.4 协议(只增不改)
- `say` 客户端消息增加可选 `to`(智能体 persona id,字符串);服务端校验它属于本房间的 `agents` 配置,否则忽略并给 `notice agent_off`(不报错、消息照发)。
- 语音上传(核对 `routers/rooms_voice.py` 的上传接口与 `rooms/voice.py`)增加可选表单字段 `to_agent`(同上);服务端把它记在语音记录 / 消息元数据里,转写成功后触发一次智能体回合,**问题文本 = 转写文字**;转写文字不进任何日志(沿用既有规则)。
- 路由优先级:`@ai` 别名 > `@名字` > 回复规则 > `to` / `to_agent`;一条消息至多触发一个智能体回合。
- 带练:`agent_tutor.on_message` 同时接受 `kind == "voice"` 且转写成功的消息(由转写完成时调用,而不是上传时);仍只接受「当前被点名的成员」的回答(核对现有校验)。
- 协议文件 `server/app/rooms/protocol.py` 与 `web/src/features/rooms/protocol.ts` 同步,契约夹具重录;新增字段对旧客户端无影响。

## 4. `@ai` 并入默认智能体(D3)

- **默认智能体**:房间配置里 `agents` 的第一个;没有配置则为内置 `builtin:coach`(英语教练)。房主在房间设置里改第一个就是改默认。
- `@ai`、`@AI`、`@助手`(现有 `_MENTION` 能匹配的写法,核对)路由给默认智能体,得到完整的智能体体验(查词、已学词、记忆、过程只给提问者)。
- **删除旧通道**:`RoomConnection._answer` 这条公共回答路径、`rooms.answer` 提示词模板(`DEFAULT_ANSWER_TEMPLATE`、管理端模板编辑项、夹具 `rooms_prompts_legacy.json` 中仅属于它的部分)、只服务它的设置 / 计数 / 测试一并删除或改写。**私聊写作助手(`rooms.assist`、assist 车道、助手面板)不动。**
- **总开关关闭时**(`AGENTS_ENABLED=false` 或房间被静音):`@ai` 返回 `notice agent_off`,消息照常发布(与现在 `@名字` 一致);不再有「没有智能体也能用的 AI 回答」。
- 现有的 `ai_public`、`ai_muted`、`ai_queue`、`ai_per_room_hour` 等限制继续适用于所有智能体回合(旧名字保留,避免迁移)。
- 提示文案:输入框占位符和帮助里的 `@ai` 改为「@AI(英语教练)」之类,显示默认智能体的真实名字。
- 管理后台:房间详情、提示词管理里与 `rooms.answer` 相关的入口移除(保留历史版本数据,不删表)。

## 5. 回复纯英文,中文单独放(D4、D5)

### 5.1 规则
- **公开文本只含英文**:联机里智能体的回复、带练的点评与题目、1:1 里智能体回合的回复,都要求简单、符合水平的英文,不含中文。人名 / 专有名词若含中文,保留在公开文本里,但**朗读时跳过**(§5.3)。
- **中文说明放在 `note_zh`**(可选字符串,≤ 80 字,朗读永远不读,界面默认折叠,点「中文」才显示)。
- 是否生成 `note_zh`:新增用户级智能体设置 `zh_note`,取值 `auto` | `always` | `never`,默认 `auto`;`auto` = 角色水平为 A2 / B1 时生成,B2 以上不生成。联机里按**提问者**的设置;带练按带练开启者。`never` 时模型被明确告知不要写中文。

### 5.2 生成与解析
- **带练**:`<<META>>` 的 JSON 增加 `note_zh`(替换原先的「简评:」中文行);现有 `hint` 改为英文,另加 `hint_zh`(可选)。题目 / 点评正文纯英文。解析器对缺失 / 非法字段一律回落为空,不报错。
- **聊天模式(1:1 与联机的普通回合)**:提示词要求回复末尾可选地追加一行 `<<ZH>> <中文说明>`;解析器(与现有 `StreamFilter` 同一思路,支持标记被拆在不同数据块)边流边剥掉标记之后的内容,不进公开文本,结束后得到 `note_zh`。
- **服务端兜底过滤**:公开文本落库前,逐句检测中文(CJK 统一表意文字 / 假名 / 全角标点句),含中文的句子从公开文本移除;若 `note_zh` 为空,则用被移除的中文句拼成 `note_zh`(截断到 80 字)。只被过滤、不报错、不重试模型。
- 提示词(`ROOM_RULES`、`ROOM_LINE`、带练块、内置角色提示里要求输出中文的部分)全部改为英文输出;内置角色中文提示词(如「英语教练」)可保留中文指令但必须明确「回复只用英文」。
- **传输**:1:1 SSE 的 `done` 事件增加可选 `note_zh`(缺省 = 没有);联机把 `note_zh` 放在公开消息的元数据里(`RoomMessage.meta.note_zh`,核对 `meta` 列与 `out_one` / 重放 / 隐藏逻辑);1:1 随 assistant 消息保存在 `messages.agent_trace` 的 `note_zh` 键里(无迁移;`check_stored` 与 `compact_trace` 需放行并限长 80 字)。带练条的 `hint_zh` 随 `agent_tutor` 帧 / 带练 REST 状态下发,不进消息文本。
- 契约:`done.note_zh`、`meta.note_zh`、`tutor.hint_zh` 都是**可选键**;缺省视为没有(沿用「`Event.to_dict` 丢弃 null」的约定)。

### 5.3 朗读兜底(两边都做)
- 网页统一的 `speakable(text)`:朗读前去掉所有中文 / 假名 / 全角标点片段,压缩多余空白;结果为空则不朗读。联机的朗读按钮、1:1 的逐句朗读管线(`use-auto-speak` / `sentence-stream`)、带练的「听一遍」都走它。
- `note_zh` 与 `hint_zh` **永远不会进入朗读文本**:它们不在消息文本里,朗读入口只取消息正文。

## 6. 数据与迁移
- **无迁移**:`zh_note` 存在 `agent_user_settings` 的 JSON 里;`note_zh` 存在消息元数据 / `agent_trace` JSON 里;`to` / `to_agent` 是请求字段,语音记录的目标存在现有元数据 JSON 里(若语音表没有可用 JSON 列,计划作者须提出最小迁移并在 Ruling 里说明,编号 `0018`)。
- 老消息没有 `note_zh`,界面不显示「中文」按钮。

## 7. 隐私与安全(必须保持)
- 转写文字、问题文本、`note_zh` 永不进日志 / URL / 错误;路由到智能体的语音转写只在内存和消息表里。
- `to` / `to_agent` 只能指向本房间配置里的智能体;不能借它指定任意角色。
- 服务端过滤只处理公开文本;不得因过滤丢失用户的原消息。

## 8. 不做
- 空闲自动关闭「对象」;服务端保存「对象」状态;给 1:1 加 `@`。
- 把 `note_zh` 自动翻译成别的语言;语音识别结果的人工修改。
- 改动私聊写作助手。
