## 2. 设计

### 2.1 服务端
- 新表(迁移 `0020`,「核对」当前 head 是否仍为 `0019`):`changelog_entries`(`id`、`published_at` 可空 = 草稿、`entry_date`、`version` 可空、`title_zh`、`title_en`、`items` JSON `[{tag, zh, en}]`、`created_by`、`created_at`、`updated_at`、`archived_at`)与 `changelog_reads`(`user_id` 主键、`last_seen_id`、`updated_at`)。条目数 ≤ 20 条、每条文字 ≤ 200 字,逐键校验。
- 用户接口(登录即可;内容公开,日志与错误里不记内容):`GET /api/changelog?cursor=`(只返回已发布,按发布时间倒序,每页 20 条,带 `unread`:比 `last_seen_id` 新的已发布条数;新用户首次 `unread` 最多 3);`POST /api/changelog/seen {upto_id}`(只前进不后退,幂等)。必须排在 `stubs` 之前。
- 管理接口(`/api/admin/changelog`,`perms.require`):列表(含草稿)、创建、修改、发布 / 下架、删除;写操作进审计链(只记条目 id 与动作,不记正文)。
- 导入命令:读取 `docs/changelog/*.json`,按 (`entry_date`, `title_zh`) 幂等创建草稿,不改已发布条目;不放进迁移。

### 2.2 网页
- 练习页顶栏 `PageHeader` 的 `actions` 里在「练习清单」前加 `ChangelogEntry`(只用 `~/features/changelog` 的公共出口,不新增跨 feature 边;「核对」`features/practice/practice-page.tsx` 是否能经扩展点而不是直接导入);新 feature `web/src/features/changelog/`:未读钩子(`useChangelogUnread`,把 `unread` 缓存在内存,打开页面 1 秒后调用 `seen`)、列表页(月份分组、类型筛选、首条展开、未读「新」角标、折叠 > 2 条、分页滚动加载、骨架 / 空 / 失败重试 / 离线缓存标注)、文案走自己的懒加载文案;没有任何已发布条目时入口图标不显示。
- 首次出现未读时的一次性小提示用本机偏好记住已显示。主包增量目标 ≤ 0.5 kB gzip,页面全部懒加载。

### 2.3 管理端
- `admin/src/features/changelog/*`(仅桌面,窄屏沿用占位页):列表 + 编辑器 + 预览;`components/layout.tsx` 加导航项。

## 3. 隐私、验证与不做
- 内容是公开的发布说明,不含用户数据;日志、审计只记 id 与动作。
- 测试:接口(权限、分页、unread、seen 只前进、草稿不可见)、迁移往返、导入命令幂等、网页页面各状态、入口红点与一次性提示、管理端页面、隐私(caplog)、契约夹具 + 网页契约测试、架构测试不放宽。
- **未验证**:真机 iPhone 上的入口红点与提示环、页面滚动与分页体验、管理端真实浏览器布局。
- 不做:推送通知、按用户 / 用户组定向、点赞评论、富文本 / 图片、自动从 git 生成并直接发布。
