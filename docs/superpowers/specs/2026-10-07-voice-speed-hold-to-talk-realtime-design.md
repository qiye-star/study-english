# 语音提速与抗噪、按住说话、实时对话(设计文档)

日期:2026-10-07
范围:`web/`(录音、对话页输入栏、实时通话页)与 `server/`(流式识别中继、实时对话中继、TTS 流式)。基于[对话页增强](2026-10-05-chat-enhancements-design.md)与[语音对话](2026-10-05-voice-chat-and-bilingual-design.md)。

## 1. 需求(用户原话归纳)

1. 优化语音识别速度(现在太慢);提升抗杂音能力——旁边有人说话时不应被识别。
2. 语音输入从"点一下开始、再点一下停止"改为**按住说话、松手发送**;按住后**上滑**出现"取消 / 转文字"两个落点。
3. 新增**实时对话**,像真人一样实时交流;现有模型不行就在火山方舟找实时语音交互模型,由我决定。
4. 先写计划。

## 2. 现状与慢在哪里(代码调研,未实测)

发送链路(从点停止到助手开口),`[B]`为串行阻塞:
1. 停止录音等 `stop` 事件,Safari 兜底最长 2 s `[B]`(`web/src/audio/recorder.ts`)。
2. 整段解码并重采样成 16 kHz WAV,在主线程 `[B]`(`web/src/audio/convert.ts`)。
3. 上传未压缩 WAV(约 32 KB/s)、服务端整段缓冲 + base64 `[B]`。
4. **识别 = 用多模态大模型做一次非流式 chat 调用** `[B]`(`server/app/routers/ai_audio.py`),无 `max_tokens`,提示词偏长——最大的一跳。
5. 转写出现后,聊天 SSE 开始流式;但**自动朗读要等整条回复结束、再等整段 mp3 合成完** `[B]`(`use-auto-speak.ts`、`ai_audio.py` 把火山的分块结果拼完才返回)。
6. 没有任何 VAD / 静音裁剪 / 能量门限;没有任何延迟打点。

结论:慢来自"非流式识别 + 串行的整段合成 + 无裁剪的整段上传",而不是模型本身。
抗杂音:浏览器只开了通用的 `noiseSuppression`;没有 VAD,旁人说话与用户说话无法区分,识别提示词里也没有"只转写最近说话人"的约束。

## 3. 我的判断与取舍

### 3.1 实时对话:不用火山端到端实时模型,做级联流式管线
- 火山端到端实时对话(`wss://openspeech.bytedance.com/api/v3/realtime/dialogue`)延迟最低,但:**英语能力官方只说"可进行英语对话"、不保证**;人设与大模型被锁在豆包,**无法换成 DeepSeek**,也**拿不到可控的发音纠正**;鉴权/开通方式**未验证**(声音复刻 2.0 与实时对话可能是不同产品,需要单独开通);定价未知。方舟侧未发现 API Key 直连的实时语音模型。作为英语口语教练,这些都是硬伤。
- **选定方案(级联)**:浏览器端 VAD → 流式 ASR(火山大模型流式识别 `sauc/bigmodel`,经服务端中继)→ DeepSeek 流式回复 → 按句切分 → 逐句流式 TTS(`seed-tts-2.0`)→ 浏览器 WebAudio 排队播放;支持打断。预计首个声音 1.2–2.5 s(估算,需实测)。保留现有提示词、场景、难度、语法检查、发音评测。
- 火山端到端实时仍作为**可选后备实验**写进计划末尾的 spike,只在验证了鉴权、英语质量与成本后再评估,不进入主线。

### 3.2 提速:三处同时下刀
- **识别流式化**:优先用火山流式识别(带服务端断句)。`sauc/bigmodel` 的鉴权(是否接受现有 UUID Key / 需要的资源 ID)**未验证**——计划第一步是一个只读 spike 去验证;验证失败则**降级**:保持现有识别,但做下面两项优化。
- **客户端优化(与识别提供方无关)**:AudioWorklet 直接采 16 kHz 单声道 PCM(不再 MediaRecorder + 事后解码重采样);裁掉首尾静音;停止即发送(无 2 s 兜底);上传可流式分片。
- **合成流式化**:火山 TTS 的分块结果直接透传(不再拼完再返回);自动朗读改为**按句流水线**:回复流到第一句结束就开始合成并播放,后面的句子排队。这一项对"手动发送文字/语音后的朗读"也立刻有效,**不依赖实时通话**。
- 加**延迟打点**(客户端 `performance.now` 分段 + 服务端日志只记耗时,不记文本),用数据验证提速,验收看数字。

### 3.3 抗杂音:分层,不承诺"只认本人"
- 没有可用的声纹/目标说话人能力(浏览器没有;火山侧未发现)。**不承诺**能在旁人大声说话时完全分辨。
- 分层缓解:① `getUserMedia` 约束(回声消除/降噪/自动增益保持开,`voiceIsolation` 可用则开);② **Silero VAD**(`@ricky0123/vad-web`,WASM,自托管模型与 wasm)+ **近讲能量门限**(RMS 低于阈值的"远处人声"不算开始说话);③ 实时通话里机器人说话时提高 VAD 阈值与最短语音时长(防回声误触发打断);④ 识别提示词/参数里加"只转写最近、最清晰的说话人,忽略背景人声;没有清晰前景语音则返回空"(仅对 chat 模式识别有效);⑤ 评测分数很低且转写与评测不一致时给"可能混入了他人声音"的提示(不阻断);⑥ 设置里"近讲模式/耳机建议",并说明局限。
- 验收只承诺**可复现的合成测试**(叠加背景人声的样本在阈值门限下被裁掉/不触发),不承诺真人场景;真机、嘈杂环境属**未验证**。

### 3.4 按住说话
- 输入栏的麦克风按钮改为**按住录音**(Pointer Events + `setPointerCapture`,`touch-action: none`,禁用长按菜单/选择);**松手发送**;按住后**上滑**超过阈值出现两个落点:左"取消"(丢弃)、右"转文字"(转写后**填入输入框、不发送**,方便先改再发);回到原位松手=发送。
- 极短按压(< 300 ms)视为误触,不录音,提示"按住说话"。60 s 上限自动发送(沿用)。
- **无障碍后备**:键盘/读屏用户保留"开始/结束"两次激活的行为(`Space/Enter` 切换),按钮 `aria-label` 说明;不能只留手势。
- iOS 注意:首次按下的同步手势内要完成 `getUserMedia`/AudioContext 解锁(沿用 `prime()` 约定);指针取消(来电/系统手势)视为取消,不发送;松手在录音权限弹窗期间的竞态要处理。

### 3.5 实时对话(通话模式)
- 入口:对话页顶栏"通话"按钮 → 全屏通话界面(状态:聆听 / 思考 / 说话;波形/音量;字幕滚动;挂断;静音;可选"按住说话"模式,适合嘈杂环境)。
- 传输:浏览器 ↔ FastAPI **WebSocket**(`/api/realtime`,二进制 PCM 16 kHz 上行;下行 JSON 事件 + PCM/mp3 音频块);服务端中继到火山流式识别,密钥只在服务端。认证:短期一次性 ticket(先 `POST /api/realtime/ticket` 取 60 s 有效的 ticket,再用它连 WS——避免把登录令牌放进 URL)。
- 一轮对话:VAD/服务端断句得到最终转写 → 写入会话消息(用户)→ DeepSeek 流式 → 句子切分 → 逐句 TTS → 下行播放 → 完成后写入助手消息。**打断**:用户开口(客户端 VAD,带回声保护)→ 客户端立刻停播并清空队列、发 `interrupt` → 服务端取消 LLM 与 TTS 任务;已播出的部分作为(截断的)助手消息保存。
- 与教学能力的结合:用户每句话的音频在服务端**异步**送讯飞评测(不阻塞对话),结果以事件推回、显示在字幕旁(沿用现有评测与保存规则,`save` 受限额);语法检查沿用设置开关。通话结束生成与文字对话一致的消息记录,**复盘/进度/词汇本直接可用**。
- 成本与滥用保护:通话最长 `REALTIME_MAX_MINUTES`(默认 10)、静音 `IDLE_TIMEOUT`(默认 60 s)自动挂断、每用户并发 1 路、沿用每分钟限流;每次通话/每句记录耗时与计数(不记录文本)。
- 降级:流式识别不可用时,通话模式退化为"VAD 断句 + 现有上传识别"(慢 2–4 s,界面提示"网络/服务较慢"),不整体失败。
- 不做:声纹分离、全双工回声消除自研、端到端实时模型(见 3.1)。

## 4. 服务端设计要点
- 新模块:`server/app/asr_stream.py`(火山流式识别客户端:二进制帧编解码、事件解析,**协议细节以 spike 结论为准**)、`server/app/routers/realtime.py`(ticket、WebSocket 中继、状态机、取消)、`server/app/sentence_split.py`(流式切句:英文句末标点 + 最长阈值 + 缩写保护;纯函数、带属性测试)。
- TTS:`volcengine.py` 暴露**异步生成器**逐块产出音频;`/api/ai/audio/speech` 支持 `stream=true` 的分块响应(保持原有整段行为作为默认,向后兼容)。
- 所有新接口:登录必需、按用户隔离、错误体 `{"error"}`、限流;WebSocket 的认证失败/超限/超时有明确的关闭码与客户端可翻译的错误码。
- 配置项(`config.py`):`REALTIME_ENABLED`(默认关到 spike 通过)、`REALTIME_MAX_MINUTES`、`REALTIME_IDLE_TIMEOUT_SECONDS`、`ASR_STREAM_URL`/资源 ID(密钥沿用 `.env`,**不写入文档/日志**)。
- 不新增迁移(消息、评测沿用既有表);如需记录通话时长统计,只写日志指标。

## 5. 网页端设计要点
- `web/src/audio/capture.ts`:AudioWorklet 采集 16 kHz PCM(带 `ScriptProcessor` 兜底)、环形缓冲、静音裁剪、RMS 门限;`vad.ts` 封装 Silero VAD(资源自托管,懒加载,PWA 预缓存策略要检查)。
- `use-hold-to-talk.ts`:指针手势状态机(idle → pressing → recording → armed-cancel / armed-text → 结束),纯逻辑可测(手势几何用注入的坐标)。
- `use-realtime-call.ts`:WS 连接、帧编码、播放队列(WebAudio 调度、抖动缓冲)、打断、挂断清理(必须释放麦克风与 AudioContext)、单音频焦点(与现有自动朗读/播放互斥)。
- 播放:流式 PCM/mp3 块用 WebAudio 排队;自动朗读按句流水线沿用同一播放器抽象。iOS 解锁沿用 `prime()` 约定(点"通话"那一下同步完成)。
- 隐私:通话期间有明显的"麦克风在用"指示;切后台/锁屏即暂停并提示;不保存原始音频,除非用户开了"保存录音评测"(沿用既有规则)。

## 6. 风险与未验证项
- **流式识别鉴权/协议未验证**(spike 决定走向);**火山 TTS/识别账号当前处于异常状态**(2026-10-05 起 TTS 返回 403/502),spike 与全部实时端到端验收依赖它恢复。
- iOS Safari:AudioWorklet、AudioContext 解锁、回声消除强度、指针事件在系统手势下的取消——**必须真机验证**,自动化只能覆盖逻辑。
- 抗噪只能降低而不能消除旁人声;嘈杂环境效果未验证。
- 成本:实时通话每句一次识别 + 一次 LLM + 每句 TTS;默认上限与开关必须清晰。
- 延迟数字目前是估算;以打点数据为准。

## 7. 验收标准
1. **提速可量化**:同一组样本(5 s / 15 s 语音)在优化前后用同一方法测量"点/松手→转写出现"和"回复完成→开始出声"的中位数,文档给出对比表;目标值先定为转写 ≤ 原来的 50%、首句出声 ≤ 原来的 40%(spike 后按实测修订并写明)。
2. 抗噪:合成样本测试(前景语音 + 背景人声/噪声,不同信噪比)证明门限/VAD 的丢弃与保留行为;设置与提示就位;局限写入文档。
3. 按住说话:手势状态机单元测试覆盖(短按、正常发送、上滑取消、上滑转文字、回到原位发送、指针取消、权限弹窗期间松手、60 s 上限、键盘后备);Playwright(Chromium 触摸模拟)用例。
4. 实时通话:服务端状态机/切句/取消有单元与集成测试(用假的 ASR/LLM/TTS 上游);端到端(真实上游)一轮对话 + 一次打断 + 挂断后无泄漏;消息正确保存,复盘可用。
5. 真机清单追加(按住说话、上滑手势、实时通话首声延迟、打断、回声、嘈杂环境),全部标"未验证"除非实测。
6. 桌面端目录零改动;无密钥;原有测试不退化。

## 8. 阶段(详细计划另写)
0. **Spike(只读验证)**:火山流式识别鉴权与帧协议;TTS 分块可用性;延迟基线测量(打点)。产出结论文档,决定 ASR 走向与目标值。
1. 服务端:TTS 流式透传、识别提示词/参数抗噪、(视 spike)流式识别客户端、切句、配置项。
2. 网页:采集/裁剪/VAD、按句流水线自动朗读、延迟打点。
3. 网页:按住说话 + 上滑取消/转文字。
4. 服务端+网页:实时通话(ticket、WS 中继、状态机、打断、通话界面、限额)。
5. 端到端、延迟对比、抗噪合成测试、文档、真机清单、最终回归。

可并行:阶段 1 与阶段 3 互不依赖(3 只需要现有识别接口);阶段 2 依赖 0 的结论;阶段 4 依赖 1、2。
