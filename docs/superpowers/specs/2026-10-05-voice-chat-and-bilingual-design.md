# 对话增强:语音消息 + 即时评测 + 双语 + 一键加入跟读(设计文档)

日期:2026-10-05
范围:`web/`(对话页、跟读页、查词抽屉)与 `server/`(消息关联评测、练习清单)。基于[手机网页版设计](2026-10-04-mobile-web-practice-design.md)。

## 1. 需求与我的判断

用户提出:
1. 对话里增加内容:中英对照的一键翻译;可以把句子加入跟读练习。
2. 语音输入不再是"语音转文字",而是把语音直接发出去——把练习和对话合到一个模块:既评测你说得怎么样,又和 AI 对话练口语。

**我的判断(不迎合):**

- **"把语音直接发给大模型"这一点我不建议做成主路径。** 对话用的 DeepSeek 听不了音频;方舟 2.0-lite 能听,但(a)大模型对发音的评判不稳定、不可复现,会"凭感觉"夸或挑错;(b)对话本身只需要文字内容,直接喂音频没有带来更好的对话。真正有价值的是**保留原始语音并给出可靠的发音评分**——这件事用现有的讯飞评测(确定性、有词/音素级结果)做,不靠大模型。
- **所以用户感受到的是"发语音",实现上是"语音消息 = 录音 + 转写 + 评测"**:你说一句,气泡里留着你的录音(可回放),AI 照常回复,同时给这句话打分、标出读得不好的词。这满足"练习和对话合在一个模块"的目的。
- **必须诚实告知的限制:自由说话的评测不如跟读准确。** 讯飞评测需要参考文本;自由说话时我们只有转写结果当参考。若转写把读错的词"自动纠正"成了正确的词,评测会把它判为不一致(能抓到);若转写忠实地写成了错词,评测会给高分(漏掉)。所以对话里的分数定位成**"发音提示"**,不是考试分;要精确打分,走原有的"参考文本跟读"。
- **不把跟读页并入对话页。** 两者互补:对话练"能不能说",跟读练"某一句读得准不准"。合并会丢掉按参考文本精确评分这个最可靠的能力。正确的整合是**双向打通**:对话 → 一键把某句(含 AI 纠正后的版本)送去跟读;跟读页可以先听范读(TTS)再录。
- 转写步骤的另一个问题:基于大模型的转写会"脑补"含糊发音。对话里要把转写文本展示给用户看(并高亮评测标出的词),让用户看到"系统听成了什么"——这本身就是反馈。

## 2. 功能设计

### 2.1 语音消息(替代"语音转文字填入输入框")
- 输入栏的麦克风:点一下开始、再点一下结束并**自动发送**(录音中有"取消"按钮可丢弃,不发送)。上限 60 秒。
- 发送流程(客户端编排,复用现有接口,先后顺序):
  1. 录音 → 转 16 kHz 单声道 WAV(现有模块)。
  2. `POST /api/ai/audio/transcriptions` 得到转写文本 → 立刻显示为"语音气泡"(录音时长 + 转写文本,转写失败则提示并保留录音可重试)。
  3. 转写文本作为用户消息走现有的流式对话,AI 回复开始流出。
  4. **并行**:`POST /api/speech/assessments`(`reference` = 转写文本,`save=true`,`source=chat`)得到评测;结果回来后,气泡出现分数徽标,转写文本里读得差的词变色。
  5. 回复成功后保存消息对(现有逻辑),用户消息附带 `assessment_id`。
- 转写不是英文(检测不到英文字母/中文为主):跳过评测,气泡标注"未评测(非英文)";仍照常对话。
- 语音气泡:点开展开详情(复用评测结果视图:总分、准确/流利/完整、逐词音素),有"回放录音"和"跟读这句"。
- 感知延迟:转写约几秒(实测 32 秒音频约 4 秒),转写完成即显示文本并开始回复,评测异步补上,不阻塞对话。
- 文字输入保持不变。

### 2.2 中英对照翻译
- 每条 AI 回复有"译"按钮:点击在原文下方显示中文(目标语言取"我的"页语言设置),再点收起。翻译用现有 `translateText`(带 IndexedDB 缓存),不写服务端。
- 对话顶栏"双语"开关(默认关):打开后新回复流式结束自动翻译一次(多一次 LLM 调用,有缓存)。
- 用户自己的语音/文字消息不自动翻译(可选的"译"按钮仍可用)。

### 2.3 一键加入跟读
- AI 回复按句拆分(简单按句末标点);"跟读"面板列出各句,每句有"练"(直接跳到跟读页,参考文本预填)和"收藏"(加入练习清单)。
- 查词抽屉在"选中一句/一段"(翻译态)时增加"跟读这句 / 收藏"。
- **练习清单**(新):跟读页顶部/历史页旁新增"清单"入口,条目可点进跟读、可删除。收藏来源记为 chat / lookup / manual。
- 跟读页增加**"先听范读"**按钮:用现有 TTS 朗读参考文本,再录音(听-说闭环)。

### 2.4 反馈闭环(这是把"对话"和"练习"真正连起来的部分)
- 用户消息上的"润色"按钮:让 LLM(JSON 模式)给出**更自然的说法 + 简短中文说明**(语法/用词),不改写用户原话。结果缓存。
- 润色结果里的句子有"跟读这句"——**参考文本是纠正后的句子**,用户去跟读页练正确说法并拿到精确评分。
- 会话设置里的"教练模式"(默认关):打开后,系统提示词附加"学习者在上一句可能读错的词:X、Y(发音分 N)",让 AI 自然地重述(recast)并简短提示,不打断对话。

### 2.5 明确不做(v1)
- 把音频直接喂给大模型做"教练点评"(不稳定、不可复现,先不做;若以后做,只作为额外的定性点评,不替代评分)。
- 流式/实时语音对话(WebRTC/实时 API)、打断式对话。
- 角色扮演场景模板、建议回复提示(可作为之后的独立功能)。
- 多语言评测(讯飞评测当前只接英文)。

## 3. 服务端设计(迁移 `0004`)
- `messages` 增加可空列 `assessment_id`(指向 `assessments.id`,删除评测时置空;写入时校验该评测属于当前用户)。`message_out` 返回 `assessment_id`。`POST /api/conversations/{id}/messages` 的单条消息可带 `assessment_id`。
- `assessments` 增加 `source`(`practice`|`chat`,默认 `practice`);`POST /api/speech/assessments` 接收可选表单字段 `source`;跟读历史默认只列 `source=practice`,对话产生的评测通过消息关联查看(`GET /api/assessments?source=…` 可筛选)。
- 删除对话时,级联删除其消息关联的 `source=chat` 评测及录音文件(避免孤儿文件吃配额);删除单条消息同理。需有测试。
- 新表 `practice_items`:`id`(uuid)、`user_id`、`text`(≤ 2000)、`source`、`created_at`;接口 `GET/POST /api/practice-items`、`DELETE /api/practice-items/{id}`;每用户条数上限(`MAX_PRACTICE_ITEMS`,默认 500,超限 429);相同文本去重(返回已有项)。
- 评测配额沿用现有 `RECORDING_QUOTA_MB`(对话录音也计入;60 秒 ≈ 1.9 MB,500 MB 约 260 分钟,超限提示用户清理)。

## 4. 网页端设计
- 复用:录音/WAV 模块、评测结果视图、`translateText`、`completeChat`、TTS 播放器、查词抽屉。
- 新增:语音气泡组件、`useVoiceTurn`(编排转写→对话→评测,含取消/重试/卸载清理)、句子拆分与"跟读面板"、练习清单页与 API 封装、润色调用、会话设置项(教练模式、双语默认值)。
- 跟读页接受 `state.reference`(已有)与来自清单的条目。
- 全部移动优先:录音按钮 ≥ 44 px,取消按钮易触达,键盘/安全区沿用现有布局。

## 5. 风险与未验证项
- **自由说话评测的准确性**(见 §1):需要用真实录音实测——故意读错几个词,看转写+评测能否标出;结果写进验收记录。若效果太差,降级为"只保存录音+转写,不展示分数",并保留跟读页为精确评测入口。
- **延迟与成本**:每轮语音 = 一次方舟转写 + 一次讯飞评测 + 一次 DeepSeek(+ 可选 TTS、翻译、润色)。讯飞评测的并发/配额限制我没有核实,需要在实测时观察,并在服务端对评测调用沿用现有的用户级限流。
- **iOS Safari 录音**仍未真机验证(与前一期相同;Playwright 的 WebKit 没有 MediaRecorder),真机清单需追加"语音消息"项。
- 转写会"脑补"含糊发音(见 §1),展示转写文本是缓解手段,不是根治。

## 6. 验收标准
1. 服务端:迁移 `0004` 在 SQLite/Postgres 通过;`assessment_id` 校验(越权 404/422)、级联删除(行+文件)、`source` 筛选、练习清单(上限、去重、隔离)有测试;现有 390 项测试不受影响。
2. 网页端:`tsc`、单元测试、`vite build` 通过;语音消息的取消/失败重试/卸载释放麦克风有测试。
3. 真实上游端到端(Chromium 手机预设,假麦克风):语音消息 → 转写显示 → AI 流式回复 → 评测徽标出现;气泡详情可回放;"跟读这句"带参考文本跳转并可评测;翻译(单条/双语开关)与缓存命中;收藏→清单→跟读;润色→跟读纠正句;删除对话后评测与录音文件消失。WebKit 项目跑非录音用例,录音用例按既有规则跳过并写明原因。
4. 自由说话评测的实测记录(含故意读错的样例与结果);真机项标注未验证。

## 7. 阶段(详细计划另写)
1. 服务端:迁移 `0004`、消息关联评测、`source`、级联删除、练习清单接口。
2. 网页:翻译(单条+双语开关)、句子拆分与跟读面板、练习清单页、跟读页"先听范读"、查词抽屉的"跟读/收藏"。
3. 网页:语音消息(`useVoiceTurn`、语音气泡、评测徽标与详情、取消/重试)。
4. 网页:润色、教练模式、纠正句跟读闭环。
5. 端到端、自由说话评测实测、真机清单更新、文档。
