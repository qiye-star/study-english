# 对话页增强:自动朗读、场景角色扮演、提示、复盘、进度、词汇本、语速、难度(设计文档)

日期:2026-10-05
范围:`web/`(对话页、查词抽屉、"我的"页、新增复盘/进度/词汇本页面)与 `server/`(词汇本、学习统计)。基于[语音对话设计](2026-10-05-voice-chat-and-bilingual-design.md)。

## 1. 需求

用户要求:(0)**自动朗读** AI 回复,开关**默认开**;并增加此前建议的 7 项:1 场景角色扮演、2"不会说?"提示、3 复盘总结、4 学习进度页、5 词汇本(间隔复习)、6 朗读语速、7 难度等级。

## 2. 我的判断与取舍

- **自动朗读默认开意味着每条回复多一次合成调用(有成本),且 iOS/Safari 不允许脱离点击自动播放。** 做法:仅对"本次用户操作之后完成的新回复"自动朗读,不读历史消息;在用户点击(发送、结束录音、开始场景)的那一下提前解锁播放器(复用现有 `primeAudioElement`),回复完成后接着播。被浏览器拦截时(`NotAllowedError`)显示一次"点此朗读"的提示,不反复弹。真机行为仍属未验证项。
- **语速用 `HTMLMediaElement.playbackRate`(保持音高)实现,不改服务端、不增加合成调用、命中同一份缓存。** 对语音气泡的回放同样生效。比让合成接口调语速更省、更简单。
- **场景和难度不需要服务端改动:** 它们是会话配置(`config.scenario`、`config.level`)里的新键,系统提示词由客户端按预设拼装。场景预设写在客户端(i18n 标题/说明 + 英文提示词 + 英文开场白),开场白是静态文本(省一次 LLM 调用、无延迟),作为第一条助手消息保存。
- **"不会说?"提示、复盘总结用客户端调用现有的对话接口(JSON 模式)**,与查词/翻译同一模式(固定提示词、严格解析、缓存),不新增服务端接口。
- **复盘与进度的数据大部分已存在**(消息里的语法结果、评测里的逐词分数、时长),所以统计在服务端按用户汇总(一个只读接口),复盘的"事实部分"在客户端从已加载的消息汇总,"摘要/新词"部分才调用一次 LLM。
- **词汇本需要服务端表**(跨设备、有复习进度),间隔复习用最简单的盒子法(Leitner),不引入复杂算法。
- **免提通话模式不做**(语音活动检测、iOS 兼容性风险高),留待自动朗读在真机验证稳定之后。

## 3. 功能设计

### 3.0 自动朗读(`autoSpeak`,默认开)
- 会话设置里"自动朗读回复"开关;对话顶栏有一个喇叭图标快速开关(影响当前会话)。配置键缺省时按"开"处理(旧会话也默认开)。
- 触发:`send()` 完成且回复状态为 done 时;朗读内容为去 Markdown 后的文本,超过 4096 字符在句子边界截断。
- 不朗读的情形:正在录音/转写、回复出错、开关关闭、页面在后台(`document.hidden`)、同一条回复已读过、用户在回复完成前又发了新消息(过期)。
- 打断:用户发送下一条、开始录音、切换会话、卸载、手动点其他朗读/语音播放时立即停止(沿用全应用单音频焦点)。
- 失败:一次会话内最多提示一次(翻译后的错误),之后静默;不影响对话。
- 场景开场白:创建会话的那次点击里解锁,开场白保存后立即自动朗读。

### 3.1 场景角色扮演
- 新建会话入口改为"选择场景"面板:自由对话 + 8 个预设(咖啡店点单、求职面试、机场/出入境、酒店入住、看医生、租房看房、问路与交通、闲聊交友)+ "自定义场景"(一段文字,≤ 500 字符)。每个预设含:标题/说明(en + zh-CN)、英文角色提示词(含"保持角色、一次只问一个问题、适度纠正"的通用要求)、英文开场白。
- 选择后创建会话:`config.scenario = {id, custom?}`,系统提示词 = 场景提示词 + 难度提示词(见 3.7),并立即保存开场白为第一条助手消息(`POST /messages`,role=assistant)。会话名用场景标题。
- 会话页顶部显示场景名;设置里可改场景(之后的回复按新提示词)。

### 3.2 "不会说?"提示
- 输入栏旁"提示"按钮:基于最近若干轮对话,让 LLM(JSON 模式)给出 3 个可选回答 `[{text, zh}]`(按当前难度),并显示在底部面板。每条可:填入输入框、朗读、跟读(跳转跟读页)、收藏。
- 缓存:键=最后一条助手消息 id + 难度,同一条重复点不再调用;录音/转写中不可用;出错可重试。

### 3.3 复盘总结
- 对话页菜单"复盘":打开复盘面板,分三块:
  1. **事实(客户端汇总,无 LLM)**:本次对话的用户消息数、平均发音分、被标出的语法问题(按类别计数 + 列表,含改正句)、读得差的词(去重)。
  2. **摘要(一次 LLM 调用,JSON 模式)**:`{summary_zh, new_expressions:[{text, zh}], suggestions_zh:[...]}`,基于对话文本 + 事实块;结果缓存并写入会话配置 `config.recap`(带生成时间与消息数;之后消息变多则提示"已过期,重新生成")。
  3. **行动**:每个改正句/新表达/差读词都有"跟读""收藏到练习清单";新表达可"加入词汇本"。
- 不自动触发;不阻塞对话。

### 3.4 学习进度页(`/progress`,入口在"我的"页和跟读页头部)
- 服务端 `GET /api/stats?days=7|30|90` 返回:每日活跃(有用户消息或评测的日期)、连续天数、口语时长(评测录音时长之和)、用户消息数、每日平均发音分、语法问题类别 Top5、读差的词 Top10。统计在服务端 Python 里按用户的最近 N 条数据汇总(上限 5000 条消息/2000 条评测,避免 JSON 聚合的方言差异)。
- 页面:周期切换、数字卡片、每日发音分折线(内联 SVG,不引图表库)、类别条形、词表(可一键加入练习清单/词汇本)。无数据时的空状态。

### 3.5 词汇本与间隔复习
- 来源:查词抽屉(单词/短语查询结果)的"加入词汇本"、复盘的新表达、进度页的差读词、手动添加。
- 数据(迁移 `0005`):`vocabulary_items`(`id`、`user_id`、`word`(规范小写,≤ 100)、`meaning`(中文释义文本,≤ 1000)、`example`(≤ 500,可空)、`source`、`box`(0–5)、`due_at`、`reps`、`lapses`、`last_reviewed_at`、`created_at`);同用户同词去重(返回已有);每用户上限 `MAX_VOCAB_ITEMS`(默认 2000,超限 429)。
- 接口:`GET /api/vocabulary`(分页、`?due=true`)、`POST /api/vocabulary`、`DELETE /api/vocabulary/{id}`、`POST /api/vocabulary/{id}/review` `{grade: "forgot"|"hard"|"good"}`(服务端按盒子法推进:forgot→box 0 明天;hard→box 不变、间隔减半;good→box+1;间隔 `[1,2,4,7,15,30]` 天)。
- 页面 `/vocabulary`:今日待复习数、卡片(正面单词 + 朗读按钮,翻面看释义/例句,三个评分按钮)、全部词汇列表(可删除)。复习一次最多 20 张。

### 3.6 朗读语速
- 全局偏好(`localStorage`,随登出清理):0.75× / 1× / 1.25×(默认 1×);对话顶栏有快速切换,"我的"页也可设置。应用于 TTS 朗读、自动朗读、语音气泡回放、跟读页"先听范读"。实现为 `playbackRate`(`preservesPitch`)。

### 3.7 难度等级
- 会话配置 `level`:`auto`(默认,不加约束)| `A2` | `B1` | `B2` | `C1`。非 auto 时系统提示词追加固定英文要求(词汇与句长上限、少用习语、必要时简短解释生词)。创建会话(场景面板)与会话设置里都可设;"不会说?"提示与复盘摘要的提示词也带上等级。

## 4. 服务端设计要点
- 迁移 `0005`:`vocabulary_items` 表及索引(`user_id`、`(user_id, due_at)`、`(user_id, word)`)。不要对 `word` 建全局唯一索引;去重在应用层(同用户)。
- 新路由在 `stubs` 之前注册;全部登录必需、按用户隔离、错误体 `{"error"}`;`/api/stats` 只读,对每用户限流(沿用现有限流依赖)。
- 会话 `config` 现有的体积校验要核对:复盘结果(≤ 约 6 KB)与场景自定义文本不得被误拒;如需放宽,单独调整并加测试。
- 级联:删除用户的词汇不影响其他数据;删除会话不删除词汇。

## 5. 风险与未验证项
- **成本**:自动朗读(每条回复一次合成)、提示、复盘各增加调用;自动朗读默认开,开关与顶栏快速开关必须清晰。
- **iOS 自动播放**:真机未验证;降级方案是提示"点此朗读"。
- **场景提示词质量**:预设提示词需要用真实模型试聊;计划里安排一次手动抽查记录(不做自动断言)。
- **统计准确性**:发音分来自自由说话评测(见前一期文档的局限),进度页需注明"仅供参考"。
- **LLM 输出**:提示和复盘的 JSON 严格解析,失败给可重试错误,不缓存失败结果。

## 6. 验收标准
1. 服务端:迁移 `0005` 在 SQLite/Postgres 通过;词汇接口(去重、上限、隔离、复习推进、`due` 过滤)与统计接口(空数据、边界日期、限量扫描、隔离)有测试;原有 551 项不受影响。
2. 网页端:`tsc`、单元测试(连跑 3 次稳定)、`vite build` 通过;自动朗读的各不朗读情形、打断、被拦截提示;语速作用于所有播放入口;场景创建(开场白保存、朗读);提示/复盘的解析与缓存;词汇复习流程;配置保存只含变更键(沿用既有规则)有测试。
3. 真实上游端到端(Chromium 手机预设):新建场景会话→开场白出现并自动朗读(播放状态)→发送一条→回复完成后自动朗读;关闭开关后不朗读;提示面板得到 3 条可选回答;复盘面板事实块与摘要;查词加入词汇本→词汇页复习一次→下次到期时间推进;进度页显示当天数据。WebKit 跑非录音用例并写明跳过原因。
4. 真机清单追加:自动朗读(iOS 首次发送后是否自动播放)、语速切换、场景开场白朗读;全部标"未验证"除非实测。
5. 桌面端目录零改动;无密钥。

## 7. 阶段(详细计划另写)
1. 服务端:迁移 `0005`、词汇接口、统计接口、config 体积核对。
2. 网页基础:会话配置新键(`autoSpeak`、`level`、`scenario`、`recap`)与设置面板、难度提示词、语速(全局偏好 + 所有播放入口)、自动朗读(含单元测试矩阵)。
3. 网页:场景面板与开场白、"不会说?"提示。
4. 网页:复盘面板、进度页。
5. 网页:词汇本(查词抽屉入口、复习页、复盘/进度页入口)。
6. 端到端、文档、真机清单、最终回归。
